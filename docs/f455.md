# Direct F455 face (RealSense ID)

DriveOS talks to the Intel RealSense ID F455 over its USB serial port with the SDK's Python binding `rsid_py`
(SDK 3.6.1, firmware 9.16.1.1). The camera keeps the
templates and does matching and depth anti-spoofing; DriveOS only sees a status and a user id.

## Install (Pi)

`rsid_py` is built once from the RealSense ID SDK into `~/repos/RealSenseID/build-device/lib` (it must use the same
Python ABI as the DriveOS environment). DriveOS finds it with no install step, in this order:
`biometrics.f455_lib`, env `DRIVEOS_F455_LIB`, `~/repos/RealSenseID/build-device/lib`. Build it with:

    git clone --depth 1 --branch v3.6.1 https://github.com/realsenseai/RealSenseID.git ~/repos/RealSenseID
    cmake -S ~/repos/RealSenseID -B ~/repos/RealSenseID/build-device -DCMAKE_BUILD_TYPE=Release \
          -DRSID_PY=ON -DRSID_SAMPLES=ON -DRSID_PIPELINE=OFF
    cmake --build ~/repos/RealSenseID/build-device -j2

The user needs the `dialout` group for `/dev/ttyACM*`.

### Live preview in the checkout sheet

The sheet shows the camera while Face ID runs (see `hmi_lvgl/CHECKOUT_CONTRACT.md`). That needs an `rsid_py` built
with the SDK's preview support, which `-DRSID_PREVIEW=ON` adds (libjpeg-turbo is fetched during the build). Build it
next to the plain one; DriveOS prefers `~/repos/RealSenseID/build-preview/lib` when it exists:

    cmake -S ~/repos/RealSenseID -B ~/repos/RealSenseID/build-preview -DCMAKE_BUILD_TYPE=Release \
          -DRSID_PY=ON -DRSID_PREVIEW=ON -DRSID_PIPELINE=OFF -DRSID_SAMPLES=OFF -DRSID_TOOLS=OFF
    cmake --build ~/repos/RealSenseID/build-preview -j2

Without it Face ID works as before and the sheet keeps the face icon. Settings: `biometrics.preview` (default on),
`preview_fps` (12), `preview_size` (240), `preview_mirror` (true). Frames stay in RAM and never touch the disk.

## Config

    biometrics.face_backend = "auto"   # auto | f455 | aibox | sim | none
    biometrics.f455_lib     = "~/repos/RealSenseID/build-device/lib"
    biometrics.face_timeout_s = 8.0
    biometrics.mode         = "auto"   # auto | live | simulated   (env DRIVEOS_BIOMETRICS__MODE)

`auto` uses the F455 when it is present, otherwise a companion face-verification service over HTTP (`aibox`). In the AppImage,
use **Settings → Face ID** for up to five driver/passenger profiles, selection, name/role editing, consent, enrollment,
re-enrollment, existing-face linking and deletion. Only the selected driver can approve checkout. The UI uses
`face_profile_select`, `face_profile_edit`, `enroll_face_start`, `enroll_face_link`, `enroll_face_delete` and
`enroll_face_cancel`; raw camera user ids are not shown.
Source-checkout CLI enrollment remains `driveos enroll --face --name Asha`; delete with `driveos enroll --face --delete`.

## Evidence mapping

| F455 result | DriveAuth evidence |
|---|---|
| `Success` for the DriveOS-enrolled user | confident, P = 0.95 (the camera reports a decision, not a similarity) |
| `Spoof*`, `TooManySpoofs` | available, not confident (never a low score) |
| `Forbidden`, timeout, another enrolled user | available, not confident |
| no device, SDK missing, port busy, device error | unavailable |

## Simulated mode

`biometrics.mode = "simulated"` (the default when there is no voice enrollment) scripts voice and face outcomes
(`accept`, `impostor`, `spoof`, `unavailable`; `biometrics.sim_voice` / `sim_face`, or the dev WebSocket command
`sim_outcome {modality, outcome}`) and feeds them through the same `ExtVoice` / `ExtFace` adapters into the real
DriveAuth ladder, with the one-time code on the phone banner. `state.shop.checkout.auth.sim` is `true`.
